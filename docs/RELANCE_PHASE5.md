## 3. Suite : lot 5.5b — `ela-eval code`

Objectif : évaluer l'Atelier Code pour comparer les modèles, depuis la ligne de commande et le backoffice.

- **Jeu** `eval/code.yaml` : `version`, `subjects` — `id` (ex. `UTS-C01`), `level`, `course`, `topic` (le texte saisi dans l'Atelier, ex. « simulation et estimation d'un AR(1) »), `expect_figure` (oui/non), `expected_terms` (liste, ex. `adfuller`, `arch_model`, `coint`), `notes`. Modèle Pydantic dans `ela.eval.code` (ou `dataset.py`), ids uniques.
- **Déroulé par sujet** (`ela.eval.code.evaluate_code`, runner `CodeRunner` avec fabrique d'engine injectable pour les tests) : `ElaEngine(user_level=level).generate_code(topic, "Python")` → `sandbox.extract_code` → `sandbox.syntax_error` + `engine.fix_code` (≤ 2 passes, comme `_ensure_parses`) → `sandbox.run_code` (client direct, `user_id=None`) → si échec (`status != ok`) et `CODE_AUTO_FIX` : `engine.fix_code(code, stderr)` puis ré-exécution (une fois) ; si `ok` sans sortie chiffrée, compter `has_output = False` (pas de correction « Compléter » dans l'évaluation, à confirmer). Mesures par sujet : `generated`, `syntax_ok` (avant correction), `run_ok_first`, `run_ok`, `n_fixes`, `has_output` (`sandbox.has_numbers`), `has_figure` (`len(result.images) > 0`, comparé à `expect_figure`), `terms_found` (tous les `expected_terms` présents dans le script final, insensible à la casse), `timeout` (`status == "timeout"`), `latency_generation_s`, `latency_run_s`, `error`, `code` (script final), `stdout`, `stderr` (tronqués). Métriques : clés déjà listées dans `METRIC_SPECS["code"]` + `n`, `n_errors` ; `by_course` (`questions`, `run_ok_rate`, `fixes_mean`).
- **CLI** : `ela-eval code --label … [--course …] [--ids …] [--limit N] [--no-fix] [--result …]`, dataset `EVAL_CODE_DATASET` (défaut `eval/code.yaml`), progression `[i/n] ID  gén 3.2s  exéc ok  corrections=0`, rapport `…-<label>-code.json` avec `run_metadata("code", …)` (sans l'URL du bac à sable, seulement `sandbox: true`). `ela-eval compare` fonctionne déjà pour `code`.
- **Backoffice** : `EVAL_KINDS += ("code",)`, `MODE_LABELS["code"] = "Évaluation de l'Atelier Code"`, option dans le formulaire (champs cours / limite / modèle ; pas de juge ni de `k` ; estimation « N sujets ≈ N à 3N appels LLM + N exécutions »), refus clair si `SANDBOX_URL` est vide (`settings.sandbox_enabled`) ; `dataset_facts` lit aussi `code.yaml` (cours et comptes par cours) ; page du rapport et CSV : champs déjà prévus ; onglet de filtre `code`.
